Git history and undoing mistakes, explained by watching it work

Everyone makes mistakes with Git, and almost every mistake can be fixed. First you learn to read the history. Then you learn which undo commands are safe and which ones can hurt. Press Play to watch, or click the commands yourself. A soft voice and gentle sounds explain each step.

CommandWhat it doesSafety
git log --oneline --graph --allDraws the history of every branch as a pictureSafe: only reads
git blame <file>Shows who last changed each line, and in which commitSafe: only reads
git restore --staged <file>Takes a file out of the staging area. Edits stay.Safe
git restore <file>Throws away your edits and brings back the last commitDestructive: edits can’t be recovered
git revert <commit>Adds a new commit that does the oppositeSafe, even for pushed commits
git reset --soft / --mixedMoves the branch back and keeps your changesCareful: rewrites history
git reset --hardMoves the branch back and throws the changes awayDestructive, though reflog can often rescue the commits
git reflogA diary of where HEAD has been, so lost commits can be foundSafe: only reads

The commits, names and dates here are made up. Output is simplified, so your real Git may format a few lines differently. Voice uses your browser’s built-in speech, and sound starts after your first click.
