PySpark broadcast joins, explained by watching them work

A join is easy on one computer. On a cluster, the rows you need to match sit on different machines. Spark has two main ways to deal with that. Pick a tab, press Play, watch the rows travel and listen to the sounds. Then test yourself with real-world scenarios in the last tab.

Teaching model: 3 executors, 36 orders and 3 country rows, all made up. The plans are simplified, and the memory number in the last tab is illustrative. With Adaptive Query Execution on (the default in recent Spark versions), Spark can also switch to a broadcast join at runtime when a table turns out to be small.
