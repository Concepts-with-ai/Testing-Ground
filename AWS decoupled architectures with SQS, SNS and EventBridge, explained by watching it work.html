Decoupled architectures on AWS: SQS, SNS and EventBridge

Loosely coupled means one part can slow down, fail or scale without taking the others with it. Here you can experiment: move the sliders, break things on purpose and watch the numbers change. A soft voice explains what is happening. Press Play story for a guided tour of any tab.

ServiceModelRemember for the exam
SQS StandardQueue. Consumers pull. Each message is handled by one consumer.At-least-once delivery, best-effort ordering, nearly unlimited throughput. Visibility timeout (default 30 s, up to 12 h). Retention default 4 days, up to 14. Long polling up to 20 s. Dead-letter queue. Delay up to 15 min.
SQS FIFOQueue with strict order inside a message group.Exactly-once processing, message group ID, deduplication (5-minute window), name ends in .fifo. Lower throughput than Standard.
SNSPub/sub topic. SNS pushes a copy to every subscriber.Fan-out. Subscribers: SQS, Lambda, HTTP/S, email, SMS, mobile push. Filter policies. No storage, so put an SQS queue behind it for durability. FIFO topics exist.
EventBridgeEvent bus with rules that match patterns and route to targets.AWS service events, SaaS partner events, custom events, schedules. Content-based filtering. Up to 5 targets per rule. Archive and replay. Schema registry.

Teaching simulations: the numbers are small and made up so you can see the effects. Check AWS’s current documentation for exact limits, because quotas change. SQS message size is 256 KB (AWS has been raising it, so verify), and larger payloads normally go to S3 with a pointer in the message.
